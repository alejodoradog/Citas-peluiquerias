# 0.5 Configuración de Claude Code
Objetivo: convertir las reglas del proyecto en configuración que se cumple sola.
Plan: Fase 0, tarea 0.5, y sección "Configurar Claude Code".
Pasos:
1. Reglas en `.claude/rules/` para migraciones y `src/app`.
2. Skills `nueva-migracion`, `nueva-pantalla` y `cerrar-tarea`.
3. Subagentes `revisor-spec` y `revisor-seguridad`.
4. Hooks: Prettier y ESLint tras editar; typecheck y pruebas afectadas en `Stop`; bloqueo de `.env*` y de comandos contra producción.
5. MCP: Supabase local, Playwright y GitHub con token en variable de entorno.
6. Actualizar `CLAUDE.md`.
Lista cuando:
- Los hooks se prueban disparando de verdad.
- Los subagentes y skills aparecen tras recargar.
- `claude mcp list` muestra el estado real de cada servidor.
- Lint, typecheck y pruebas pasan.
Fuera de alcance: las reglas de negocio.
Requiere del dueño del proyecto: crear el token de GitHub limitado a este repo y guardarlo como variable de entorno.
Decisiones:
- `Stop` deja de insistir tras 3 intentos fallidos seguidos y avisa, para no quedar en un ciclo sin fin.
- `Stop` solo corre si hay cambios sin commit en `.ts`, `.tsx`, `.mts`, `.mjs`, `.json` o `.css`.
- Aún no existe producción. Se bloquean `supabase link`, `supabase db push`, `--linked`, `--project-ref`, `--db-url` y `vercel --prod`. Cuando exista `barberias-dev`, hay que permitir su enlace y bloquear producción por su referencia.
- Los subagentes son de solo lectura y reciben la lista de archivos cambiados.
- Los hooks usan `command` + `args`, sin shell, porque por defecto en Windows dependerían de Git Bash.
- `@playwright/mcp` queda fijo en 0.0.83, publicada hace más de dos semanas.
Límite conocido: `guard.mjs` busca patrones en el texto de los comandos. Evita descuidos, pero no impide que un programa ejecutado lea `.env.local` por dentro.
Resultados de las pruebas de hooks:
- Lectura de `.env.local`: bloqueada por `permissions.deny`, antes de llegar al hook. `guard.mjs` la bloquea por separado en sus casos de prueba.
- Comando `supabase db push`, búsqueda con glob `.env*` y comando de sonda: bloqueados por el hook en una sesión real. Lectura de `.env.example`: permitida.
- 32 casos de `guard.mjs` correctos, incluida la entrada inválida, que también bloquea.
- Prettier reformateó un archivo de prueba y ESLint reportó un `any` que no podía corregir.
- `Stop` detectó en una sesión real un error de tipos y una prueba fallida, e hizo seguir trabajando. Fuera de sesión confirmó el tope: bloquea en los intentos 1 y 2, avisa en el 3 y reinicia.
