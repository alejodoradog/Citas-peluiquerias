# 0.4 CI y vista previa
Objetivo: cada pull request se revisa solo y se publica en una URL de Vercel.
Plan: Fase 0, tarea 0.4.
Pasos:
1. Crear el workflow de GitHub Actions con lint, typecheck y pruebas.
2. Conectar Vercel al repositorio.
3. Abrir un pull request de prueba.
Lista cuando: un pull request de prueba pasa todos los chequeos y se ve publicado en una URL de Vercel. Es también el criterio de cierre de la Fase 0.
Fuera de alcance: despliegue a producción y migraciones automáticas.
Decisiones:
- El repo sigue como `Citas-peluiquerias` hasta que el dueño decida renombrarlo.
- `barberias-dev` no se crea todavía, porque la app aún no lee de la BD.
- `supabase test db` entra a CI en la fase 1, cuando haya migraciones.
- Un PR por rama, apilados en orden; solo el último ejecuta el workflow hasta que se fusionen.
- Playwright corre en todos los PR, no solo en los que van a `main`.
